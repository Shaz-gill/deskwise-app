# Better-Auth Setup (with Prisma + PostgreSQL)

Steps to set up [Better Auth](https://www.better-auth.com/) in a project already using Prisma with a PostgreSQL datasource.

## 1. Install Better Auth

```bash
bun add better-auth
```

**What this generates:** Nothing on disk yet — installs the `better-auth` package into `node_modules` and adds it to `dependencies` in `package.json`.

## 2. Generate a secret

```bash
bunx @better-auth/cli@latest secret
```

**What this does:** Generates a cryptographically secure secret used to sign and encrypt sessions/tokens. Typically printed to the terminal for you to copy into your `.env` as `BETTER_AUTH_SECRET` (or written directly if `.env` already exists, depending on CLI version) — no other files are created.

## 3. Create your auth config

**File:** `lib/auth.ts`

```ts
import { betterAuth } from 'better-auth';
import { prismaAdapter } from 'better-auth/adapters/prisma';
import prisma from '../db';

export const auth = betterAuth({
   basePath: '/api/auth',
   database: prismaAdapter(prisma, {
      provider: 'postgresql',
   }),
   emailAndPassword: {
      enabled: true,
      disableSignUp: true,
   },
});
```

This is a manually created file (not generated by a command) — it wires Better Auth to your existing Prisma client, sets the auth API base path, and configures email/password auth with sign-up disabled (useful if you're pre-provisioning users rather than allowing open registration).

## 4. Generate the required Prisma models

```bash
bunx @better-auth/cli@latest generate
```

**What this generates:** Reads your `lib/auth.ts` config and adds the required models — `User`, `Session`, `Account`, `Verification`, etc. — into `prisma/schema.prisma`. It does not touch the database itself, only the schema file.

## 5. Create the tables in the database

```bash
bunx prisma migrate dev --name add_better_auth_tables
```

**What this generates:** Creates a new migration file under `prisma/migrations/<timestamp>_add_better_auth_tables/` containing the SQL to create the Better Auth tables, applies it to your database, and regenerates the Prisma Client to include the new models.

## Notes

- Make sure `BETTER_AUTH_SECRET` (and any other required env vars, e.g. `DATABASE_URL`) are set in `.env` before running the migration.
- Re-run step 4 (`generate`) any time you change your Better Auth config in a way that affects the schema, then re-run step 5 (`migrate dev`) to apply it.
